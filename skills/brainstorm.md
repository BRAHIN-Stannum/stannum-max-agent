# SKILL: brainstorm
**Trigger:** `#brainstorm` · "tengo una idea" · "qué piensan de" · "exploremos" · "ideemos"
**Módulo:** GOBERNANZA
**Output:** Ideas capturadas, catalogadas y convertidas en propuestas accionables

---

## Propósito

Capturar ideas antes de que se pierdan y darles estructura suficiente para evaluar si merecen entrar al pipeline. Una idea sin estructura es ruido; una idea briefeada es una oportunidad.

---

## Protocolo

### PASO 1 — CAPTURAR (sin interrumpir)
Dejar que Brahin termine de expresar la idea completa. No preguntar todavía.

### PASO 2 — REFLEJAR
Repetir la idea en una oración para confirmar entendimiento.
"Entendí que querés [X] para lograr [Y]. ¿Correcto?"

### PASO 3 — CATALOGAR

| Dimensión | Opciones |
|-----------|---------|
| Tipo | Producto · Proceso · Comercial · Tecnología · Comunidad |
| Impacto potencial | Alto (OKE) · Medio (mejora) · Bajo (micro) |
| Urgencia | Esta semana · Este mes · Backlog |
| Área | DITEG · GECO · EVENTOS · MARK · ECLI · ADFIN · IA |
| Recursos necesarios | Solo MAX · Equipo · Budget · Externo |

### PASO 4 — EXPANDIR (si hay tiempo)
3 variaciones de la idea (más conservadora / tal cual / más ambiciosa).
Potencial bloqueante principal para cada una.

### PASO 5 — DECISIÓN

```
💡 IDEA CAPTURADA — [fecha]
Nombre: [título corto]
Tipo: [tipo] · Área: [área]
Impacto: [alto/medio/bajo] · Urgencia: [urgencia]

RESUMEN:
[2-3 líneas]

VARIACIONES:
- Conservadora: [...]
- Como propuesta: [...]
- Ambiciosa: [...]

BLOQUEANTE PRINCIPAL: [qué puede impedir esto]

PRÓXIMO PASO:
→ Backlog / Briefear con `#brief` / Derivar a [área]
```

---

## Reglas

- Siempre capturar primero, catalogar después — no cortar el flujo creativo
- Si la idea se convierte en proyecto → usar `#brief` para estructurarla formalmente
- No descartar ideas — catalogarlas en backlog aunque parezcan de baja prioridad
- Si la idea contradice un OKR o la Bernabéu Cash Rule → mencionarlo, no ignorarlo
